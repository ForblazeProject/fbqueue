# Windows 版の実装範囲と制限

この文書は **v0.9.6の仕様と実機検証範囲**を示します。Windows別名起動を廃止したスナップショットは、2026-11-13に Windows AMD64 / PowerShell 5.1 で同梱ソースから再ビルドされ、**19/19ケース成功、スキップ・エラー・未実行なし**でした。明示コマンドによる履歴・IDフィルタ、別名拒否、基本実行・環境・nodefile・スケジューリング・キャンセル・walltime・アーカイブを対象ケースで確認しました。

検証対象と制限は [Windows実機検証記録](WINDOWS_VERIFICATION.md) を参照してください。Linux と同じ復旧機能を Windows に要求するものではありません。実機検証はv0.9.6への版数更新前のスナップショット（表示はv0.9.5）で実施しました。現在のCargo版数はv0.9.6です。検証時には実行ファイルの SHA-256 と検証プロファイルを記録し、版数だけで対象を判定しません。今回の合格は配布済みv0.9.5や未検証の機能・環境の合格を意味しません。

## 実装されている範囲と検証上の制限

| 機能 | Windows の実装・条件 |
|---|---|
| 投入・状態表示・履歴・キャンセル | `fbqueue.exe sub/stat/del/daemon` に統一。実行ファイル名を変えずに使う。Windowsの `qsub.exe` / `qstat.exe` / `qdel.exe` 等の別名起動は状態初期化前に終了コード2で拒否する。Linuxの別名は維持。PBS形式は `fbqueue.exe stat --style pbs` で利用できる。 |
| `.bat` / `.cmd` | `cmd /c` で実行。Unix シェル構文への変換はしない。 |
| `.ps1` | PATH 上の Windows PowerShell `powershell` を `-ExecutionPolicy Bypass -File` 付きで起動。PowerShell 7 の `pwsh` を自動選択する機能はない。 |
| capacity / cost、キュー、優先度 | 共通のスケジューラ実装。CPU/GPU の実使用量測定・強制隔離ではなく、申告した cost による起動数制御。この点は Linux でも同じ。 |
| 依存・遅延開始・range/list・walltime | 今回のWindows実機テストで対象ケース成功。時刻精度や全ての入力形式を保証するものではない。 |
| PBS 形式の環境変数・nodefile | 共通実装あり。nodefile は要求 cost 分の行を生成するが、実際の Windows MPI / 各ソルバーとの連携は未検証。 |
| 正の整数 cost、容量超過拒否、入力エラー時 rc=2、待機キャンセル履歴 | v0.9.6の共通実装に含まれる。配布済み v0.9.5 に遡って適用される仕様ではない。 |
| 自動アーカイブ | PATH 上の外部 `tar` コマンドが必要。テストでは `tar.exe` がない場合、このケースだけ理由付き SKIP とする。 |

## Linux 専用のため Windows にはないもの

- 永続的な `daemon.lock` と `flock` による排他的なデーモン所有権。
- boot ID・PID・プロセス開始時刻と pidfd による停止対象の検証。
- 再起動時の自動再実行を避ける `UNKNOWN` 保留と、boot の違いを証明した `INTERRUPTED` 処理。
- 復旧・履歴衝突・I/O エラー時に全体の新規実行を止める Linux の保留処理と、`recovery.error` の永続ラッチ。

Windows のデーモン管理は従来の PID ファイルと `tasklist` に依存します。複数の CLI を同時に起動した場合の排他や、PID 再利用に対する安全性を Linux 開発版と同等とは扱いません。`daemon status` も PID ファイルの表示であり、実際のプロセスの同一性を証明する表示ではありません。

## 特に重要な停止・復旧の違い

| 操作・状態 | Windows | Linux 開発版 |
|---|---|---|
| `daemon stop` | PID ファイルの PID に `taskkill /PID ... /F /T` を実行。ワーカーを含むプロセスツリーも強制終了する実装。 | 検証したデーモンだけを停止し、既存ワーカーは止めない。 |
| デーモンを起動し直したときの running 記録 | `new` に戻して先頭から再実行する。元ワーカーが生存していると重複実行の危険がある。 | 自動再実行せず保留。 |
| 実行中ジョブのキャンセル・walltime | `taskkill /F /T` による強制終了。正常終了処理やチェックポイント保存は保証しない。 | Unix プロセスグループに対する強制終了。こちらもアプリ側の保存処理は保証しない。 |

**Windows のジョブ実行中にデーモンを強制終了・再起動する運用は避けてください。** 停止した計算の外部出力や副作用はロールバックされません。実行が不明な記録を見つけても、残存プロセスを確認せずに再投入しないでください。

`taskkill /T` は Windows Job Object による強い封じ込めではありません。任意の離脱・別サービス経由のプロセス生成まで停止できるとは保証しません。今回のテスト基盤では後始末用に Job Object を使いますが、**これはテスト基盤の機能であり、FBQueue 本体に実装したものではありません**。

## シェル・互換性・安全性の限界

- `.sh` の shebang を Windows ネイティブで解釈して Linux 同様に実行する機能はない。必要なら WSL 等を明示的に呼び出す別の運用を検討する。本テストは WSL を要求しない。
- PBS / SGE / Slurm はディレクティブとコマンド形式の一部への互換にとどまり、フル互換ではない。MPI・実アプリの Windows 移植性とは別問題。
- `.ps1` の `-ExecutionPolicy Bypass` はそのプロセスの起動指定であり、スクリプトが安全である証明ではない。本体は `-NoProfile` を指定しないため、既存の PowerShell プロファイルも実行に影響し得る。
- 空白・日本語パス、引用符、長いパス、他の文字コードは Windows 固有の検証が必要。今回のテストには空白入り作業パスと日本語・空白入り `.ps1` 名を含めるが、全ての引用符やパス形式を網羅しない。
- 複数ユーザー共有・ネットワークファイルシステム・厳密な権限分離は本テストの保証対象外。まず単一ユーザー・単一マシン・ローカルストレージで使う。

## Windows テストの位置づけ

`tests/windows/Run-Tests.ps1` は PowerShell 5.1 と Windows API を使う、Windows 10/11 向けの実機テストキット。Python、Pester、管理者権限は不要。ただし C# の `Add-Type` と Job Object が許可される環境が必要で、組織ポリシーなどで利用できなければ実行前にエラーとして停止する。

- **Development**: v0.9.6の仕様を検証するプロファイル名。
- **Released095**: 公開済み v0.9.5 向け。v0.9.6で導入した契約のケースは明示的に SKIP。バージョン文字列からの自動判定はしない。
- **PASS / FAIL / SKIP / ERROR / NOT_RUN** を区別し、ゼロ件実行や未完了を成功として報告しない。
- 実行ファイルの SHA-256、選択プロファイル、ケース別判定、終了コード・標準出力・標準エラー、許可したメタデータ、後始末結果を ZIP に保存する。ネットワークへの自動送信はしない。
- 生の `.job`、ユーザー環境変数一覧、ユーザーの HOME は返却 ZIP に含めない。パス名やエラー文にユーザー名などが含まれる可能性はあるので、送信前に確認する。

テストキットとソースの検査・ハーネス単体テストは Linux 上の PowerShell でも実行できるが、Windows API・FBQueue Windows バイナリの実行結果の代用にはならない。
